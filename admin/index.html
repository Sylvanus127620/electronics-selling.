One-time setup

Everything below is done once, in your GitHub account.

  1. Create a repository (for example electronics-selling) and push this project to the main branch.
  2. GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  3. Set Repository access: Only select repositories → your site repository. Set an expiry date.
  4. Under Permissions → Repository permissions → Contents, choose Read and write. Nothing else is required.
  5. Copy the token once, paste it in the Repository tab here, and connect. The token lives in memory for this tab only.
  6. Enable Pages (Settings → Pages → Deploy from a branch → main / root) or connect the repo to Cloudflare Pages.

How saving works

Each save calls PUT /repos/{owner}/{repo}/contents/data/products.json with the current file SHA, so GitHub records a normal commit and your host rebuilds the site. Expect 30–90 seconds before a change is visible. Commits from this dashboard are serialized so two saves cannot overwrite each other with a conflicting SHA.

Images are uploaded the same way to images/uploads/ as base64. Keep them under ~1MB each — the Contents API rejects large payloads and every byte stays in your git history forever.

Security limitations — read this

  • No server-side authentication. The passphrase gate on this page is cosmetic; it is enforced in the visitor's browser and can be bypassed by anyone who reads the source.
  • The token is visible in DevTools (network requests and the Authorization header) while the session is active, and to any script or extension running on this origin.
  • XSS is the real risk: a third-party script on this origin could read the in-memory token. Do not add untrusted scripts to this site.
  • Mitigations used here: the token is never written to localStorage, sessionStorage, cookies or any file; it is cleared on sign-out and lost when the tab closes. Scope it to a single repository with Contents-only permission and a short expiry.
  • Revoke immediately at GitHub → Settings → Developer settings if a device is lost or you suspect exposure. Revoking invalidates it instantly, everywhere.
  • Strongest option: keep the repository private, or place /admin behind Cloudflare Access (email one-time PIN or Google SSO). The static site keeps working either way.
  • HTTPS is required — GitHub Pages and Cloudflare Pages serve it by default. Never open this dashboard over plain HTTP.
